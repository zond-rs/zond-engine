## Findings to verify empirically, then file with CVSS

- **X1 (High, CVSS 7.5 AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H)** — port-list amplification: `HostAcc::extend` (`src/import/report/nmap.rs:860`) expands each `<extrareasons ports="1-65535"/>` (~30 bytes) into 65,535 `Port` values (each ~100+ bytes with a heap `String` for the reason) with no bound on ports per host at the import layer; `MAX_PORTS_PER_HOST` is enforced only later in `Host::add_port`, after the allocation. The 256 MiB `Bounded` document ceiling does not help — this is amplification, not document size. Probe: a ~3 KB document through `ReportFormat::Nmap.read`, measure ports and peak RSS.
- **X2 (CVSS 5.3 AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:L/A:N)** — `Run::scan_info` (`src/import/report/nmap.rs:625`) adds `numservices` values with unchecked `+=` on u128; two ~2^127 values overflow (release: silent wrap → wrong probe count in the rebuilt scope; debug: panic). Same class as the epoch overflow the fuzzer found and was fixed with `checked_add`. Probe: three `<scaninfo numservices="...">` elements.
- **X3–X6 (no CVSS / informational)** — module doc claims entities are interpreted "only in text that was asked for" but `read_value` resolves/refuses them in unkept attributes too (doc bug; code is more spec-correct than documented); CDATA content is dropped during text capture; the DOCTYPE `SYSTEM`/`PUBLIC` refusal is evadable with whitespace/case but the actual control (no fetching, ever) is structural; duplicate attributes accepted with first-wins.
- **X7 (Low)** — quadratic addresses×ports work in the target-side `emit` (`src/import/nmap.rs:204`): K addresses × N ports parse work from K+N elements. Probe: measure CPU for a moderate K=N document.
- **Positive verdict to document** — xml.rs proper: no unsafe, no panics reachable (all indexing guarded), every loop guaranteed to progress, all accumulations bounded (name 64 B, values ≤ max, text 512 B, markup ≤ max_line_bytes, elements 2^24, depth 64 with iterative walking), entity expansion structurally impossible, UTF-8 checked at both capture points. The twelve documented claims hold.
